### 4.6 달리기 경주 풀이 리뷰 — ✅ 완료

작성한 첫 번째 `solution`이 이 문제의 표준 풀이에 더 가깝다.

```java
public String[] solution(String[] players, String[] callings) {
    Map<String, Integer> playerMap = new HashMap<>();

    for (int i = 0; i < players.length; i++) {
        playerMap.put(players[i], i);
    }

    for (String player : callings) {
        int currentRank = playerMap.get(player);
        int previousRank = currentRank - 1;
        String previousPlayer = players[previousRank];

        players[currentRank] = previousPlayer;
        players[previousRank] = player;

        playerMap.put(previousPlayer, currentRank);
        playerMap.put(player, previousRank);
    }

    return players;
}
```

좋았던 점:

- 배열이 `인덱스 → 선수` 순위표 역할을 한다.
- Map이 `선수 → 인덱스` 역방향 조회를 담당한다.
- 두 선수가 바뀔 때 배열과 Map을 모두 갱신했다.
- 문제에서 1등 선수는 호출되지 않는다고 보장하므로 `currentRank - 1`이 음수가 되지 않는다.

복잡도:

```text
N = 선수 수
M = 호출 수

초기 Map 구성: O(N)
모든 추월 처리: 평균 O(M)
전체: 평균 O(N + M)
추가 공간: O(N)
```

`HashMap`의 기본 `get`, `put`은 해시가 적절하다는 전제에서 평균 O(1)이다. 지역 변수는 null이 나올 수 없는 문제 조건이므로 `Integer`보다 `int`를 사용해도 된다. 변수 선언은 구현체보다 인터페이스 타입으로 두면 의도가 더 잘 드러난다.

```java
Map<String, Integer> playerMap = new HashMap<>();
```

#### 두 Map과 Stream을 사용한 `solution1`

두 번째 풀이도 정답을 만들 수 있지만 이 문제에서는 비용이 더 든다.

```text
선수 → 순위 Map
순위 → 선수 Map
마지막 entrySet 정렬
```

- Map을 두 개 관리하므로 상태 동기화 지점과 메모리가 증가한다.
- `HashMap<Integer, String>`은 `int` 순위를 `Integer`로 boxing한다.
- `HashMap`은 순서를 보장하지 않으므로 반환 전에 키 정렬이 필요하다.
- 마지막 정렬 때문에 O(N log N)이 추가된다.
- `entry.getValue()`는 이미 `String`이므로 `String.valueOf(...)`는 필요 없다.

Stream 부분만 정리하면 다음과 같다.

```java
return rankMap.entrySet()
        .stream()
        .sorted(Map.Entry.comparingByKey())
        .map(Map.Entry::getValue)
        .toArray(String[]::new);
```

이 코드는 다음 순서로 동작한다.

```text
entrySet()                 키와 값을 한 쌍으로 꺼냄
stream()                   Stream 파이프라인 생성
sorted(comparingByKey())   순위 키 오름차순 정렬
map(Map.Entry::getValue)   Entry를 선수 이름으로 변환
toArray(String[]::new)     String[]로 결과 생성
```

이 Stream은 학습용으로 유용하지만 `달리기 경주`의 최종 풀이에는 첫 번째 배열+Map 방식이 더 단순하고 빠르다.

### 4.7 HashMap에서 자주 쓰는 메서드 — ✅ 완료

공식 문서:

- [Java 17 HashMap](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashMap.html)
- [Java 17 Map](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Map.html)

| 목적 | 메서드 | 예시 |
|---|---|---|
| 값 저장·교체 | `put` | `map.put(key, value)` |
| 값 조회 | `get` | `map.get(key)` |
| 기본값과 함께 조회 | `getOrDefault` | `map.getOrDefault(key, 0)` |
| 키 존재 확인 | `containsKey` | `map.containsKey(key)` |
| 없을 때만 저장 | `putIfAbsent` | `map.putIfAbsent(key, value)` |
| 없을 때 값을 만들어 저장 | `computeIfAbsent` | 그룹별 List·Set 생성 |
| 기존 값과 새 값을 합침 | `merge` | 빈도·합계 누적 |
| 매핑 삭제 | `remove` | `map.remove(key)` |
| 키·값 쌍 순회 | `entrySet` | `for (Map.Entry<...> entry : ...)` |
| 키만 순회 | `keySet` | `for (String key : map.keySet())` |
| 값만 순회 | `values` | `for (int value : map.values())` |

#### 빈도 세기

```java
Map<String, Integer> count = new HashMap<>();

for (String value : values) {
    count.put(value, count.getOrDefault(value, 0) + 1);
}
```

`merge`를 사용한 같은 풀이:

```java
for (String value : values) {
    count.merge(value, 1, Integer::sum);
}
```

#### 그룹별 List 만들기

```java
Map<String, List<Integer>> group = new HashMap<>();

for (int i = 0; i < categories.length; i++) {
    group.computeIfAbsent(
            categories[i],
            key -> new ArrayList<>()
    ).add(i);
}
```

`computeIfAbsent`는 키가 없거나 값이 null일 때 함수를 실행해 초기값을 만든다.

#### `get()`의 null 주의

```java
Integer value = map.get(key);
```

결과가 null이면 다음 두 경우를 구분하기 어렵다.

```text
키가 존재하지 않음
키는 존재하지만 값이 null
```

구분이 필요하면 `containsKey(key)`를 함께 사용한다. 코테에서는 값으로 null을 저장하지 않도록 설계하는 편이 단순하다.

### 4.8 `entrySet`, `keySet`, `values` — ✅ 완료

```java
}
```

`entrySet`, `keySet`, `values`가 반환하는 컬렉션은 원본 Map을 반영하는 view다. 순회 중 원본 Map에 새로운 키를 넣거나 제거하는 구조적 변경은 피한다.

또한 `HashMap`의 순회 순서는 보장되지 않는다. 다음처럼 작성했다고 키 정렬 결과가 되는 것이 아니다.

```java
for (Map.Entry<Integer, String> entry : rankMap.entrySet()) {
    // 키 오름차순이라는 보장이 없음
}
```

순서가 필요하면 Entry를 List 또는 Stream으로 옮긴 뒤 명시적으로 정렬한다.

### 4.9 Stream 핵심 연산 — ✅ 완료

공식 문서:

- [Java 17 Stream](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/stream/Stream.html)

Stream은 다음 세 단계로 읽는다.

```text
소스 생성 → 중간 연산 → 최종 연산
```

```java
String[] result = rankMap.entrySet()
        .stream()                            // 소스 생성
        .filter(entry -> entry.getKey() > 0) // 중간 연산
        .sorted(Map.Entry.comparingByKey())  // 중간 연산
        .map(Map.Entry::getValue)            // 중간 연산
        .toArray(String[]::new);              // 최종 연산
```

자주 쓰는 연산:

| 연산 | 의미 |
|---|---|
| `filter(predicate)` | 조건을 만족하는 원소만 유지 |
| `map(function)` | 원소를 다른 형태로 변환 |
| `sorted()` | 자연 순서로 정렬 |
| `sorted(comparator)` | 지정한 기준으로 정렬 |
| `distinct()` | 중복 제거 |
| `limit(n)` | 앞에서 n개만 사용 |
| `count()` | 원소 개수 반환 |
| `toArray(generator)` | 원하는 배열 타입으로 변환 |
| `toList()` | Java 16 이상에서 List로 반환 |

Stream의 중간 연산은 최종 연산이 호출될 때 실행된다. `sorted()`까지만 작성하고 `toArray`, `toList`, `count` 같은 최종 연산을 호출하지 않으면 결과를 소비하지 않는다.

#### 필터 → 정렬 → 값 추출

```java
List<String> popularNames = count.entrySet()
        .stream()
        .filter(entry -> entry.getValue() >= 2)
        .sorted(
                Map.Entry.<String, Integer>comparingByValue()
                        .reversed()
                        .thenComparing(Map.Entry.comparingByKey())
        )
        .map(Map.Entry::getKey)
        .toList();
```

정렬 기준:

```text
1차: 빈도 내림차순
2차: 이름 오름차순
```

Java 17의 `Stream.toList()` 결과는 수정할 수 없는 List다. 결과에 원소를 추가·삭제해야 한다면 다음처럼 새 `ArrayList`로 감싼다.

```java
List<String> mutableNames = new ArrayList<>(popularNames);
```

### 4.10 `sorted`, `List.sort`, `Arrays.sort` 비교 — ✅ 완료

공식 문서:

- [Java 17 Comparator](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Comparator.html)

| 방식 | 원본 변경 | 반환·결과 |
|---|---|---|
| `stream.sorted(comparator)` | 원본 컬렉션을 직접 바꾸지 않음 | 정렬된 새 Stream |
| `list.sort(comparator)` | List 자체를 변경 | 반환값 없음 |
| `Arrays.sort(array)` | 배열 자체를 변경 | 반환값 없음 |

```java
List<Integer> numbers = new ArrayList<>(List.of(3, 1, 2));

List<Integer> sortedCopy = numbers.stream()
        .sorted()
        .toList();

// numbers: [3, 1, 2]
// sortedCopy: [1, 2, 3]
```

```java
numbers.sort(Comparator.naturalOrder());

// numbers 자체가 [1, 2, 3]으로 변경
```

다중 기준 Comparator:

```java
Comparator<String> comparator =
        Comparator.comparingInt(String::length)
                .thenComparing(Comparator.naturalOrder());
```

문자열 길이 오름차순으로 정렬하고, 길이가 같으면 사전순으로 정렬한다.

### 4.11 코딩테스트에서 Stream을 사용할 기준 — ✅ 완료

Stream이 잘 맞는 경우:

- 계산이 끝난 결과를 필터링·정렬·변환해 출력
- Map Entry를 정렬해 배열이나 List로 변환
- 파이프라인이 짧고 각 단계가 한눈에 보임

일반 반복문이 더 나은 경우:

- `달리기 경주`처럼 배열과 Map 상태를 동시에 변경
- 반복문 중간에 여러 분기와 조기 종료가 있음
- 인덱스가 핵심인 시뮬레이션
- 성능과 디버깅의 단순성이 중요한 내부 반복

실전 원칙:

```text
상태를 계속 바꾸는 계산: for
계산이 끝난 결과의 필터·정렬·변환: Stream 고려
```

### 6.2 기록이 0건인 기준 행 보존 — ✅ 완료

예시 `base`:

| id | name |
|---:|---|
| 1 | A |
| 2 | B |
| 3 | C |

예시 `detail`:

| id | base_id | created_at |
|---:|---:|---|
| 101 | 1 | 2026-07-03 |
| 102 | 1 | 2026-07-20 |
| 103 | 2 | 2026-06-30 |
| 104 | 2 | 2026-08-01 |

7월 기록만 세되, 7월 기록이 없는 `base`도 결과에 남기는 쿼리:

```sql
SELECT
    base.id,
    COUNT(detail.id) AS detail_count
FROM base
LEFT JOIN detail
  ON detail.base_id = base.id
 AND detail.created_at >= '2026-07-01'
 AND detail.created_at <  '2026-08-01'
GROUP BY base.id;
```

예상 출력:

| id | detail_count |
|---:|---:|
| 1 | 2 |
| 2 | 0 |
| 3 | 0 |

행별 해석:

- `base.id = 1`: 7월 상세 기록이 2건이므로 `2`
- `base.id = 2`: 상세 기록은 있지만 6월과 8월 기록뿐이므로 `0`
- `base.id = 3`: 상세 기록 자체가 없으므로 `0`

`LEFT JOIN`의 `ON` 단계에서 7월 기록만 연결하므로, 조건에 맞는 오른쪽 행이 없는 `base.id = 2, 3`도 NULL 확장 행으로 남는다. `COUNT(detail.id)`는 NULL을 세지 않으므로 결과가 0이다.

주의:

```text
COUNT(detail.id) = 0
COUNT(*)         = 1
```

NULL 확장 행도 하나의 행이므로 `COUNT(*)`를 쓰면 기록이 없는 그룹이 1로 계산될 수 있다.

#### 날짜 조건을 WHERE에 둔 잘못된 비교

```sql
SELECT
    base.id,
    COUNT(detail.id) AS detail_count
FROM base
LEFT JOIN detail
  ON detail.base_id = base.id
WHERE detail.created_at >= '2026-07-01'
  AND detail.created_at <  '2026-08-01'
GROUP BY base.id;
```

예상 출력:

| id | detail_count |
|---:|---:|
| 1 | 2 |

`base.id = 2`의 6월·8월 기록은 `WHERE`에서 제거된다. `base.id = 3`의 NULL 확장 행도 `NULL >= 날짜`가 참이 아니므로 제거된다. 그 결과 7월 기록이 없는 기준 행이 모두 사라지고 사실상 INNER JOIN과 비슷한 결과가 된다.

### 6.3 조건부 집계 — ✅ 완료

조건을 `score >= 80`이라고 가정한 예시 `records`:

| group_id | score |
|---|---:|
| A | 90 |
| A | 70 |
| A | 85 |
| B | 60 |
| B | 75 |
| C | 100 |

예시 쿼리:

```sql
SELECT
    group_id,
    MAX(CASE WHEN score >= 80 THEN 1 ELSE 0 END) AS has_target,
    SUM(CASE WHEN score >= 80 THEN 1 ELSE 0 END) AS target_count
FROM records
GROUP BY group_id;
```

예상 출력:

| group_id | has_target | target_count |
|---|---:|---:|
| A | 1 | 2 |
| B | 0 | 0 |
| C | 1 | 1 |

의미:

- `MAX(...)`: 조건을 만족하는 행이 하나라도 있으면 `1`, 없으면 `0`
- `SUM(...)`: 조건을 만족하는 행의 개수

그룹 A의 `CASE` 결과는 `1, 0, 1`이다.

```text
MAX(1, 0, 1) = 1
SUM(1, 0, 1) = 2
```

`records`에 아예 존재하지 않는 그룹은 이 쿼리만으로 출력되지 않는다. 존재하지 않는 그룹까지 `0, 0`으로 보여야 한다면 그룹 기준 테이블에서 `LEFT JOIN`한 뒤 조건부 집계를 적용해야 한다.

- [ ] “제가 판단한 기준”과 “제가 한 행동”이 드러난다.
- [ ] 문장 끝이 흐려지거나 말이 지나치게 빠르지 않다.
- [ ] 화면을 자연스럽게 보고 음성이 분명하게 녹음됐다.

오늘은 다음을 하지 않는다.

- 90분 전체 AI역량검사 모의
- 공급사가 확인되지 않은 상태에서 게임별 공략 암기
- 12개 질문의 완성 원고 작성
- 표정·시선을 과장해서 연기
- 한 답변을 완벽하게 만들기 위한 3회 이상 재녹화

### 7.5 AI로 전사문 검토하기

녹화 내용을 전사한 뒤 다음 프롬프트를 사용한다.

```text
이 답변의 사실관계를 추가하거나 표현을 화려하게 바꾸지 마.

1. 첫 결론까지 걸린 문장 수
2. 질문과 직접 관련 없는 문장
3. 반복어와 군더더기
4. 한 답변에 섞인 사례 수
5. 60초 안에 들어오도록 삭제할 문장
6. 면접관이 물을 꼬리질문 3개

위 항목만 분석해 줘.
```

AI가 새 사례나 성과를 만들어 답변을 다시 쓰게 하지 않는다. 사실 확인과 최종 표현은 본인이 결정한다.

## 8. 코딩 풀이에서 AI 도움 사용 규칙

문제별 제한시간 전에는 저장 코드와 정답을 열지 않는다.

제한시간이 끝났다면 다음 프롬프트로 첫 힌트만 받는다.

```text
정답 코드나 완성된 의사코드는 주지 마.
내 접근에서 가장 먼저 잘못된 가정 하나만 질문 형태로 알려 줘.

문제:
내 접근:
현재 막힌 지점:
```

제출 후에는 다음 순서로 검증한다.

```text
이 풀이를 다음 순서로 검토해 줘.
1. 컴파일 또는 SQL 문법 위험
2. 실패하는 최소 반례
3. 시간복잡도 또는 JOIN 후 행 수
4. 경계·중복·NULL 반례

수정된 정답은 먼저 보여 주지 마.
```

AI 힌트를 사용한 문제는 오늘 완료가 아니다. 내일 같은 문제를 백지에서 다시 통과해야 복습 완료로 표시한다.

## 10. 종료 체크리스트

### Java

- [x] `HashMap.getOrDefault()`를 검색 없이 작성했다.
- [x] 배열 교환 후 위치 Map 두 항목을 모두 갱신했다.
- [x] `entrySet → stream → sorted → map → toArray` 흐름을 복습했다.
- [x] `HashSet.add()`의 반환값을 설명할 수 있다.
- [x] Comparator의 1차·2차 기준이 문제와 일치한다.
- [x] 실패율 분모가 0인 반례를 확인했다.

### SQL

- [x] 결과 한 행이 무엇을 의미하는지 먼저 적었다.
- [x] `COUNT(*)`와 `COUNT(column)`의 NULL 차이를 설명할 수 있다.
- [x] `LEFT JOIN` 오른쪽 조건을 `ON`에 둘 이유를 설명할 수 있다.
- [x] 날짜 시작일·종료일 경계를 직접 확인했다.
- [x] 차량·부모 하나당 결과가 한 행인지 확인했다.

### AI역량검사

- [ ] 자기소개·지원동기·직무강점·약점을 모두 녹화했다.
- [ ] 각 답변이 45~60초 안에 들어왔다.
- [ ] 첫 문장에서 질문에 대한 결론을 말했다.
- [ ] 제출 서류와 다른 사실이나 검증하지 않은 수치를 사용하지 않았다.
- [ ] 내일 다시 녹화할 취약 답변을 최대 1개만 골랐다.

### 내일을 위한 기록

- [ ] 오늘 실패한 문제 중 최대 2개만 골랐다.
- [ ] 각 문제에 `트리거 / 원리 / 반례` 세 줄을 남겼다.
- [ ] 정답 코드를 닫고 내일 재풀이할 시간을 정했다.
