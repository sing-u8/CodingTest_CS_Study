### 6.1 [구명보트](https://school.programmers.co.kr/learn/courses/30/lessons/42885) — ✅ 확인 완료

제한시간: **40~45분**

유형:

```text
정렬 + 투 포인터 + 그리디
```

코드 전에 답할 질문:

```text
가장 무거운 사람은 이번 단계에서 반드시 어떻게 처리되는가?
가장 가벼운 사람과 함께 태울 수 없으면 다른 누구와도 함께 탈 수 없는가?
```

핵심 불변식:

```text
매 반복에서 현재 가장 무거운 사람 한 명은 반드시 처리된다.
가장 가벼운 사람과 함께 탈 수 있을 때만 left를 증가시킨다.
```

템플릿:

```java
Arrays.sort(people);

int left = 0;
int right = people.length - 1;
int boats = 0;

while (left <= right) {
    if (people[left] + people[right] <= limit) {
        left++;
    }

    right--;
    boats++;
}
```

`left == right`인 경우에도 배는 한 번만 증가하고 두 포인터가 엇갈리므로 별도 분기 없이 처리할 수 있다. 한 명만 남았다는 의미를 코드에 명확히 드러내고 싶다면 기존처럼 `left == right` 분기를 두어도 된다.

반례:

- 한 명만 존재
- 모든 사람이 둘씩 탈 수 있음
- 아무도 둘씩 탈 수 없음
- 같은 몸무게가 여러 명

완료 기준:

- [x] 정렬 후 양끝 포인터를 사용했다.
- [x] `left == right`인 마지막 한 명이 배 한 척으로 처리됨을 확인했다.
- [x] 왜 가장 무거운 사람부터 처리해도 최적인지 설명했다.
- [x] 시간복잡도 `O(N log N)`을 설명했다.

#### 6.1.1 `int[]`에는 왜 Comparator를 전달할 수 없는가

`Arrays.sort()`에는 다음 두 계열의 오버로드가 있다.

```java
Arrays.sort(int[] array);
Arrays.sort(T[] array, Comparator<? super T> comparator);
```

`int[]`도 Java에서 배열 객체이지만, 배열의 **원소 타입 `int`는 기본형**이다. 제네릭 타입 `T`에는 기본형을 넣을 수 없고, 표준 라이브러리에도 `sort(int[], Comparator...)` 오버로드가 없다. 따라서 다음 코드는 컴파일되지 않는다.

```java
int[] people = {70, 50, 80, 50};

Arrays.sort(people, (a, b) -> Integer.compare(a, b)); // 컴파일 오류
```

기본형 배열의 오름차순 정렬은 다음 한 줄을 사용한다.

```java
Arrays.sort(people);
```

반면 `Integer[]`, `String[]`, `Person[]`처럼 원소가 참조형인 배열에는 Comparator를 전달할 수 있다.

```java
Integer[] numbers = {3, 1, 2};
Arrays.sort(numbers, (a, b) -> Integer.compare(a, b));
```

다음 `요격 시스템`에서 `int[][]`에 Comparator를 사용할 수 있는 이유도 함께 기억한다.

```java
int[][] targets = {{4, 5}, {1, 3}, {2, 4}};

Arrays.sort(targets, Comparator.comparingInt(target -> target[1]));
```

`targets`의 각 원소는 기본형 `int`가 아니라 **배열 참조형 `int[]`**이다. 따라서 바깥 배열 `int[][]`은 `T[]` 정렬 오버로드를 사용할 수 있다.

#### 6.1.2 Comparator 반환값

```java
Comparator<Integer> ascending =
        (a, b) -> Integer.compare(a, b);
```

| `compare(a, b)` 결과 | 의미 |
|---:|---|
| 음수 | `a`를 `b`보다 앞에 배치 |
| 0 | 정렬 기준상 두 값이 같음 |
| 양수 | `a`를 `b`보다 뒤에 배치 |

```java
Integer.compare(10, 20); // 음수: 10이 앞
Integer.compare(20, 10); // 양수: 20이 뒤
Integer.compare(10, 10); // 0
```

다음 뺄셈 방식은 값의 범위가 클 때 오버플로가 발생할 수 있으므로 피한다.

```java
(a, b) -> a - b                 // 피하기
(a, b) -> Integer.compare(a, b) // 권장
```

#### 6.1.3 Comparator를 작성하는 여러 방법

##### 방법 1: 람다

```java
Arrays.sort(numbers, (a, b) -> Integer.compare(a, b)); // 오름차순
Arrays.sort(numbers, (a, b) -> Integer.compare(b, a)); // 내림차순
```

##### 방법 2: 메서드 참조

```java
Arrays.sort(numbers, Integer::compare);
```

`Integer::compare`는 다음 람다와 같은 역할을 한다.

```java
(a, b) -> Integer.compare(a, b)
```

##### 방법 3: 기본 순서와 역순

```java
Arrays.sort(numbers, Comparator.naturalOrder()); // 오름차순
Arrays.sort(numbers, Comparator.reverseOrder()); // 내림차순
```

##### 방법 4: Comparator를 변수로 분리하고 뒤집기

```java
Comparator<Integer> ascending = Integer::compare;
Comparator<Integer> descending = ascending.reversed();

Arrays.sort(numbers, ascending);
Arrays.sort(numbers, descending);
```

##### 방법 5: 익명 클래스

람다가 Comparator의 `compare()` 구현을 줄여 쓴 것임을 확인할 때만 연습한다.

```java
Arrays.sort(numbers, new Comparator<Integer>() {
    @Override
    public int compare(Integer a, Integer b) {
        return Integer.compare(a, b);
    }
});
```

##### 방법 6: 객체의 여러 필드 정렬

Comparator는 단순 숫자보다 객체의 복합 정렬 기준을 만들 때 더 유용하다.

```java
peopleList.sort(
        Comparator.comparingInt(Person::getAge)
                .thenComparing(Person::getName)
);
```

의미:

```text
1차: 나이 오름차순
2차: 나이가 같으면 이름 오름차순
```

#### 6.1.4 `boxed()`의 역할

`boxed()`는 기본형 특화 스트림을 래퍼 클래스 객체 스트림으로 변환하는 중간 연산이다.

```text
IntStream    → Stream<Integer>
LongStream   → Stream<Long>
DoubleStream → Stream<Double>
```

`int[]`을 `Integer[]`로 변환하면 Comparator를 연습할 수 있다.

```java
Integer[] boxedPeople = Arrays.stream(people)
        .boxed()
        .toArray(Integer[]::new);

Arrays.sort(boxedPeople, Comparator.reverseOrder());
```

변환 흐름:

```text
int[] → IntStream → Stream<Integer> → Integer[]
```

반대로 `Integer` 원소를 다시 기본형 `int`로 바꿀 때는 `mapToInt()`를 사용한다.

```java
int[] primitiveNumbers = Arrays.stream(boxedPeople)
        .mapToInt(Integer::intValue)
        .toArray();
```

함께 기억할 두 메서드:

```java
.boxed()                     // int 원소 → Integer 원소
.mapToInt(Integer::intValue) // Integer 원소 → int 원소
```

#### 6.1.5 수정 가능한 `List<Integer>`로 변환하기

Java 16부터 사용할 수 있는 `Stream.toList()`의 반환 리스트는 수정할 수 없다.

```java
List<Integer> numbers = Arrays.stream(people)
        .boxed()
        .toList();

numbers.sort(Integer::compare); // UnsupportedOperationException
```

정렬할 리스트가 필요하면 수정 가능한 구현체를 명시한다.

```java
List<Integer> numbers = Arrays.stream(people)
        .boxed()
        .collect(Collectors.toCollection(ArrayList::new));

numbers.sort(Integer::compare);
```

또는 `toList()` 결과를 새 `ArrayList`로 복사한다.

```java
List<Integer> numbers = new ArrayList<>(
        Arrays.stream(people)
                .boxed()
                .toList()
);

numbers.sort(Comparator.reverseOrder());
```

`Collectors.toList()`는 반환 구현체와 수정 가능 여부를 명세상 보장하지 않는다. 수정할 목적이라면 `Collectors.toCollection(ArrayList::new)`가 가장 명확하다.

#### 6.1.6 스트림에서 바로 정렬하기

```java
Integer[] ascending = Arrays.stream(people)
        .boxed()
        .sorted()
        .toArray(Integer[]::new);

Integer[] descending = Arrays.stream(people)
        .boxed()
        .sorted(Comparator.reverseOrder())
        .toArray(Integer[]::new);
```

#### 6.1.7 구명보트에서의 최종 선택

Comparator 학습용 코드는 다음처럼 작성할 수 있다.

```java
Integer[] sortedPeople = Arrays.stream(people)
        .boxed()
        .toArray(Integer[]::new);

Comparator<Integer> ascending = Integer::compare;
Arrays.sort(sortedPeople, ascending);
```

하지만 구명보트는 기본형의 오름차순 정렬만 필요하다. 실제 제출에서는 박싱·언박싱과 추가 배열을 만들 필요가 없는 다음 코드가 적합하다.

```java
Arrays.sort(people);
```

최종 회상:

```text
int[]       → Arrays.sort(array)
Integer[]   → Arrays.sort(array, Integer::compare)
내림차순    → Arrays.sort(array, Comparator.reverseOrder())
List<T>     → list.sort(comparator)
int[][]     → 각 원소 int[]가 참조형이므로 Comparator 사용 가능
boxed()     → 기본형 스트림을 래퍼 객체 스트림으로 변환
```

### 6.2 [요격 시스템](https://school.programmers.co.kr/learn/courses/30/lessons/181188) — ✅ 학습 완료

제한시간: **40~45분**

유형:

```text
구간 끝점 정렬 + 그리디
```

저장 자료:

- [Solution.java](../../java/src/main/java/platform/programmers/Greedy/요격_시스템/Solution.java)
- [풀이 및 질의응답](../../java/src/main/java/platform/programmers/Greedy/요격_시스템/풀이.md)

코드 전에 답할 질문:

```text
왜 시작점이 아니라 끝점이 빠른 순서로 정렬하는가?
구간이 열린 구간 (s, e)라는 조건이 경계 비교에 어떤 영향을 주는가?
```

템플릿:

```java
Arrays.sort(targets, Comparator.comparingInt(target -> target[1]));

int missiles = 0;
int selectedEnd = -1;

for (int[] target : targets) {
    int start = target[0];
    int end = target[1];

    if (start >= selectedEnd) {
        missiles++;
        selectedEnd = end;
    }
}
```

`selectedEnd`는 실제로 끝점에서 발사한다는 뜻이 아니라, 현재 선택한 요격 위치가 `end` 직전이라는 것을 정수 비교로 표현한 값이다. 다음 구간의 시작점이 `selectedEnd`와 같으면 열린 구간에서는 같은 미사일로 요격할 수 없으므로 새 요격이 필요하다.

반례:

```text
(1, 4), (4, 5)        경계가 같지만 겹치지 않음
(1, 5), (2, 4)        포함 관계
(1, 3), (2, 5), (4, 6) 연쇄적으로 일부만 겹침
```

완료 기준:

- [x] 끝점 오름차순으로 정렬했다.
- [x] `start >= selectedEnd` 경계를 설명했다.
- [x] 한 번 선택한 끝점이 가능한 많은 구간을 포함하는 이유를 설명했다.
- [x] 시간복잡도 `O(N log N)`을 설명했다.

질의응답 회상:

```text
Q. 왜 끝점을 기준으로 정렬하는가?
A. 가장 먼저 끝나는 구간은 그 끝점보다 왼쪽에서 반드시 처리해야 하며,
   끝점 직전을 선택해야 뒤 구간과 함께 요격할 가능성이 가장 크기 때문이다.

Q. target -> target[1]은 무엇인가?
A. target은 [s, e] 형태의 int[] 한 행이고 target[1]은 끝점 e이다.
   comparingInt는 이 값을 정렬 키로 꺼내 작은 끝점부터 비교한다.

Q. 왜 start >= selectedEnd이면 새 요격이 필요한가?
A. start가 더 크면 기존 위치가 현재 구간의 왼쪽에 있고,
   같아도 구간이 열린 구간이어서 경계에서는 요격할 수 없기 때문이다.

Q. selectedEnd에서 실제로 발사하는 것인가?
A. 아니다. selectedEnd보다 아주 조금 작은 실수 좌표를 선택했다는 대표값이다.

Q. int[][]에는 왜 Comparator를 사용할 수 있는가?
A. 바깥 배열의 원소가 기본형 int가 아니라 참조형 배열 int[]이기 때문이다.
```

## 11. 오늘의 종료 기준

오늘의 성공 기준은 선택 문제 수가 아니다.

```text
AI 기본 4문항 녹화 완료
+ 경험형 2문항 녹화 완료
+ Java 그리디 2문제
+ SQL JOIN·집계 2문제
```

이 네 묶음을 끝냈다면 학습을 종료한다. 선택 문제는 내일 일정에 영향을 주지 않는 범위에서만 진행한다.
