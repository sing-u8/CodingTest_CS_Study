# 요격 시스템 풀이 및 질의응답

> 문제: [프로그래머스 — 요격 시스템](https://school.programmers.co.kr/learn/courses/30/lessons/181188)  
> 분류: Greedy, 구간 정렬  
> 핵심: 끝점 오름차순 정렬 후, 끝점 직전에 요격

## 1. 문제를 구간 문제로 바꾸기

각 폭격 미사일은 개구간 `(s, e)`로 주어진다.

```text
s < 요격 위치 x < e
```

한 좌표 `x`에서 발사한 요격 미사일은 `x`를 내부에 포함하는 모든 폭격 구간을 한 번에 요격한다. 따라서 문제는 다음과 같이 바꿀 수 있다.

```text
모든 개구간의 내부에 적어도 하나가 포함되도록
최소 개수의 실수 좌표를 선택한다.
```

## 2. 왜 끝점 오름차순으로 정렬하는가

가장 먼저 끝나는 구간은 그 끝점보다 왼쪽에서 반드시 요격해야 한다.

```text
(1, 4)를 요격하려면 1 < x < 4
```

이때 너무 왼쪽에서 요격하면 뒤에 등장할 구간과 함께 처리할 가능성이 줄어든다. 따라서 허용되는 위치 중 가장 오른쪽인 `4 바로 직전`을 선택한다.

```text
실제 개념상의 위치: 3.999...
코드에서 저장할 값: 4
```

가장 빨리 끝나는 구간의 끝점 직전을 선택하면:

- 현재 구간을 요격할 수 있다.
- 그보다 늦게 끝나는 다른 구간들과 겹칠 가능성이 가장 크다.
- 기존 위치로 처리할 수 없는 다음 구간을 만났을 때만 새 요격 미사일을 추가하면 된다.

## 3. 정렬 코드 이해하기

```java
Arrays.sort(
        targets,
        Comparator.comparingInt(target -> target[1])
);
```

### 3.1 `targets`와 `target`의 타입

```java
int[][] targets = {
        {4, 8},
        {1, 4},
        {10, 14},
        {4, 5}
};
```

`targets`의 원소 하나는 `int[]`이다.

```text
targets      : int[][]
targets[0]   : int[]  → {4, 8}
targets[0][0]: int    → 시작점 4
targets[0][1]: int    → 끝점 8
```

따라서 람다의 `target`은 구간 한 행을 나타내는 `int[]`로 추론된다.

```java
target -> target[1]
```

의 의미는 다음과 같다.

```text
int[] 구간 한 개를 받아서
그 구간의 1번 인덱스인 끝점 e를 반환한다.
```

타입을 직접 쓰면 다음과 같다.

```java
Comparator.comparingInt((int[] target) -> target[1]);
```

### 3.2 `comparingInt()`의 동작

`Comparator.comparingInt()`는 각 원소에서 `int` 정렬 키를 추출하고, 그 키를 오름차순으로 비교하는 Comparator를 만든다.

다음 두 코드는 같은 의미다.

```java
Comparator.comparingInt(target -> target[1])
```

```java
(a, b) -> Integer.compare(a[1], b[1])
```

더 풀어 쓰면 다음과 같다.

```java
(a, b) -> {
    int firstEnd = a[1];
    int secondEnd = b[1];

    return Integer.compare(firstEnd, secondEnd);
}
```

정렬 전:

```text
[4, 8]    → 정렬 키 8
[1, 4]    → 정렬 키 4
[10, 14]  → 정렬 키 14
[4, 5]    → 정렬 키 5
```

정렬 후:

```text
[1, 4]
[4, 5]
[4, 8]
[10, 14]
```

`Arrays.sort()`는 새 배열을 반환하지 않고 `targets` 자체의 행 순서를 변경한다.

### 3.3 `int[][]`에는 왜 Comparator를 사용할 수 있는가

`int[]`의 원소는 기본형 `int`이므로 다음 코드는 사용할 수 없다.

```java
int[] numbers = {3, 1, 2};
// Arrays.sort(numbers, comparator); // 사용 불가
```

반면 `int[][]`의 원소는 배열 참조형 `int[]`이다.

```text
int[]   정렬 원소: int
int[][] 정렬 원소: int[]
```

따라서 `int[][]`은 객체 배열용 `Arrays.sort(T[], Comparator)` 오버로드를 사용할 수 있다.

## 4. 순회 코드 이해하기

```java
int interceptorCount = 0;
int selectedEnd = -1;

for (int[] target : targets) {
    int start = target[0];
    int end = target[1];

    if (start >= selectedEnd) {
        interceptorCount++;
        selectedEnd = end;
    }
}
```

### 4.1 `selectedEnd`의 정확한 의미

```java
selectedEnd = end;
```

은 끝점 `end`에서 실제로 발사한다는 뜻이 아니다. 구간이 개구간이므로 끝점에서는 요격할 수 없다.

정확한 의미:

```text
selectedEnd보다 아주 조금 작은 위치에서 발사했다.
```

예를 들어 `selectedEnd == 4`이면 실제 개념상의 위치는 `3.999...`이다. 실수 좌표를 코드로 만들 필요 없이 끝점만 대표값으로 저장한다.

### 4.2 기존 요격 미사일로 처리되는 조건

```java
start < selectedEnd
```

현재 구간이 이전 끝점 직전의 좌표를 포함하므로 기존 요격 미사일로 함께 처리할 수 있다.

```text
이전 selectedEnd = 5
현재 구간 = (3, 7)

3 < 5이므로 5 바로 직전의 좌표는 (3, 7) 내부에 있다.
```

### 4.3 새 요격 미사일이 필요한 조건

```java
start >= selectedEnd
```

현재 구간은 이전에 선택한 위치를 포함하지 않으므로 새 요격 미사일이 필요하다.

특히 `==`가 중요한 이유는 개구간이기 때문이다.

```text
이전 구간: (1, 4)
현재 구간: (4, 5)

이전 발사 위치는 4 바로 직전
현재 구간은 4보다 큰 위치부터 시작
따라서 하나의 요격 미사일로 같이 처리할 수 없다.
```

그러므로 조건은 `>`가 아니라 `>=`이다.

```java
if (start >= selectedEnd) {
    interceptorCount++;
    selectedEnd = end;
}
```

## 5. 예제 추적

입력:

```text
[[4,5], [4,8], [10,14], [11,13], [5,12], [3,7], [1,4]]
```

끝점 오름차순 정렬:

```text
(1, 4)
(4, 5)
(3, 7)
(4, 8)
(5, 12)
(11, 13)
(10, 14)
```

| 현재 구간 | 조건 | 처리 | 개수 | `selectedEnd` |
|---|---|---|---:|---:|
| `(1, 4)` | `1 >= -1` | 새 요격 | 1 | 4 |
| `(4, 5)` | `4 >= 4` | 새 요격 | 2 | 5 |
| `(3, 7)` | `3 < 5` | 기존 요격으로 처리 | 2 | 5 |
| `(4, 8)` | `4 < 5` | 기존 요격으로 처리 | 2 | 5 |
| `(5, 12)` | `5 >= 5` | 새 요격 | 3 | 12 |
| `(11, 13)` | `11 < 12` | 기존 요격으로 처리 | 3 | 12 |
| `(10, 14)` | `10 < 12` | 기존 요격으로 처리 | 3 | 12 |

정답은 `3`이다.

## 6. 그리디 선택이 최적인 이유

끝점이 가장 빠른 구간을 `I = (s, e)`라고 하자.

1. `I`를 요격하려면 반드시 `s < x < e`인 좌표 하나를 선택해야 한다.
2. `e` 직전보다 더 왼쪽의 좌표를 고를 이유가 없다.
3. 좌표를 `e` 직전으로 옮겨도 `I`는 계속 요격된다.
4. 나머지 구간들은 `I`보다 끝점이 빠르지 않으므로, 오른쪽으로 옮긴 좌표가 뒤 구간과 겹칠 가능성은 줄지 않는다.
5. 따라서 어떤 최적해도 첫 요격 위치를 `e` 직전으로 바꿀 수 있다.
6. 이 위치로 처리되지 않는 다음 구간에 대해서 같은 선택을 반복한다.

이것이 끝점 오름차순 그리디가 전체 최적해를 보장하는 이유다.

## 7. 전체 Java 풀이

```java
import java.util.Arrays;
import java.util.Comparator;

class Solution {

    public int solution(int[][] targets) {
        Arrays.sort(
                targets,
                Comparator.comparingInt(target -> target[1])
        );

        int interceptorCount = 0;
        int selectedEnd = -1;

        for (int[] target : targets) {
            int start = target[0];
            int end = target[1];

            if (start >= selectedEnd) {
                interceptorCount++;
                selectedEnd = end;
            }
        }

        return interceptorCount;
    }
}
```

## 8. 복잡도

```text
정렬: O(N log N)
순회: O(N)
전체: O(N log N)
정렬을 제외한 추가 변수: O(1)
```

`targets`의 최대 길이가 500,000이므로 모든 구간 쌍을 비교하는 O(N²) 풀이는 사용할 수 없다.

## 9. 자주 틀리는 부분

### 9.1 시작점으로만 정렬하기

```java
Comparator.comparingInt(target -> target[0])
```

시작점만 빠른 순서로 보면 어느 지점에서 발사해야 뒤 구간을 최대한 많이 처리할지 결정하기 어렵다. 가장 먼저 선택이 강제되는 구간은 가장 빨리 끝나는 구간이다.

### 9.2 경계를 `>`로 비교하기

```java
if (start > selectedEnd) // 잘못된 경계
```

구간은 `(s, e)`이므로 `start == selectedEnd`인 경우에도 기존 위치로 요격할 수 없다.

```java
if (start >= selectedEnd) // 올바른 경계
```

### 9.3 끝점에서 실제로 발사한다고 이해하기

`selectedEnd`는 실제 발사 위치가 아니라 `끝점 바로 직전`을 나타내는 대표값이다.

### 9.4 뺄셈 Comparator 사용하기

```java
(a, b) -> a[1] - b[1]
```

이 문제의 값 범위에서는 오버플로가 발생하지 않지만, 일반적인 습관으로는 다음 표현이 더 안전하고 의도가 명확하다.

```java
Comparator.comparingInt(target -> target[1])
```

또는:

```java
(a, b) -> Integer.compare(a[1], b[1])
```

## 10. 질의응답 요약

### Q1. 왜 끝점 기준으로 정렬하는가?

가장 빨리 끝나는 구간은 그 끝점보다 왼쪽에서 반드시 처리해야 한다. 끝점 직전을 선택하면 현재 구간을 처리하면서 뒤 구간과 겹칠 가능성을 최대화할 수 있다.

### Q2. 왜 `target -> target[1]`인가?

`target`은 `[s, e]` 형태의 `int[]` 한 행이고, `target[1]`은 끝점 `e`이다. 이 람다는 각 행에서 정렬 키로 사용할 끝점을 반환한다.

### Q3. 어떤 원리로 오름차순이 되는가?

`Comparator.comparingInt()`는 람다가 반환한 정수 키를 기본적으로 작은 값부터 비교한다. 다음 코드와 같다.

```java
(a, b) -> Integer.compare(a[1], b[1])
```

### Q4. `selectedEnd`에서 발사하면 개구간 조건에 어긋나지 않는가?

`selectedEnd`는 실제 발사 좌표가 아니다. `selectedEnd`보다 아주 조금 작은 실수 좌표에 발사했다는 것을 정수 끝점으로 표현한 것이다.

### Q5. 왜 `start >= selectedEnd`일 때 새 미사일이 필요한가?

`start > selectedEnd`이면 현재 구간이 기존 위치보다 오른쪽에서 시작한다. `start == selectedEnd`여도 구간이 열린 구간이므로 경계에서 함께 요격할 수 없다. 따라서 두 경우를 합친 `>=`를 사용한다.

### Q6. `int[]`에는 Comparator를 못 쓰는데 `int[][]`에는 왜 가능한가?

`int[]`의 정렬 원소는 기본형 `int`이지만, `int[][]`의 정렬 원소는 참조형 배열 `int[]`이다. 따라서 `int[][]`에는 객체 배열용 Comparator 오버로드를 사용할 수 있다.

## 11. 최종 회상

```text
끝점 오름차순 정렬
→ 끝점 직전에 요격
→ start < selectedEnd면 기존 요격으로 처리
→ start >= selectedEnd면 새 요격
→ 열린 구간이므로 equality도 새 요격
```
